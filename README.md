# Discovery Camp — Telegram-бот для чек-іну

Чек-ін через QR-код, відмітка в Google Sheets, відеопривітання від лідера команди та реєстрація на майстер-класи. Хоститься на Vercel (serverless).

---

## Як це працює

### Відвідувач

1. На вході висить плакат із QR-кодом. Він відкриває бота.
2. Відвідувач пише своє **прізвище та ім'я** (як у формі реєстрації).
3. Бот знаходить збіги й показує кнопку для підтвердження.
4. Після підтвердження:
   - Бот записує Telegram ID і час чек-іну в таблицю.
   - Показує номер кімнати (якщо заповнено у формі).
   - Надсилає відеопривітання від лідера команди.
   - З'являється постійна клавіатура з кнопками:
     - **🎨 Майстер-класи** — одне повідомлення на весь день з кнопками по кожному слоту (назва + кількість вільних місць); місце проведення видно в підтвердженні після реєстрації
     - **🗓 Розклад** — розклад дня з живої таблиці-сітки табору
     - **📋 Мої реєстрації** — майстер-класи, на які зареєстрований учасник

Реєстрація — одна активна на слот (12:00-13:00 і 14:00-15:30 того самого дня — окремі слоти). Щоб змінити вибір у слоті, спершу скасуйте поточну реєстрацію (кнопка ❌), потім оберіть іншу. Ліміт місць — за наявності в каталозі; без обмежень, якщо не вказано.

---

### Лідер команди

1. Лідера додає адмін командою `/addleader <ID команди> <Прізвище Ім'я>`.
2. Лідер відкриває бота і надсилає `/leader <Прізвище Ім'я>` — так, як його зареєстрував адмін.
3. Підтверджує себе кнопкою → підключається до команди.
4. З'являється розширена клавіатура (всі кнопки відвідувача плюс):
   - **📢 Сповістити команду** — нагадує написати `/notifyteam <текст>` для розсилки учасникам
   - **✏️ Перейменувати команду** — нагадує написати `/renameteam <нова назва>`
5. Щоб встановити відеопривітання для команди — **надіслати відео або відеоповідомлення (кружечок)** боту. Бот автоматично збереже його у таблицю.

> Роль лідера підключається **тільки** командою `/leader`. Якщо просто написати ПІБ, бот шукає лише серед відвідувачів — це захищає лідерів від того, щоб хтось випадково чи навмисно зайняв їхнє ім'я.

---

### Відповідальний за майстер-клас

1. Відповідального додає адмін командою `/addresp <ID майстер-класу> <Прізвище Ім'я>` (ID — номер `№` з каталогу майстер-класів).
2. Відповідальний надсилає `/responsible <Прізвище Ім'я>` → підтверджує себе кнопкою → підключається одразу до всіх майстер-класів, закріплених на це ім'я.
3. З'являється розширена клавіатура (всі кнопки відвідувача плюс, стакується з лідерськими кнопками):
   - **👥 Учасники МК** — список учасників по кожному сьогоднішньому майстер-класу відповідального (слот, місце, кількість/ліміт)
   - **📣 Сповістити учасників МК** — нагадує написати `/notifymc <текст>`; якщо сьогодні у відповідального декілька майстер-класів/слотів, бот спершу питає, кому саме надіслати

> Роль відповідального підключається **тільки** командою `/responsible`. Якщо одна людина має кілька ролей, кожну треба підключити її власною командою — бот більше не пропонує їх автоматично. Клавіатури підключених ролей об'єднуються.

---

### Адмін

Адміна додає суперадмін командою `/addadmin <TelegramID> <Ім'я>`.

| Команда | Опис |
|---|---|
| `/addleader <ID> <ПІБ>` | Додати лідера (ID — числовий ID команди з таблиці Videos) |
| `/removeleader <ID> <ПІБ>` | Видалити лідера |
| `/listleaders` | Список усіх лідерів із статусом підключення |
| `/addresp <ID МК> <ПІБ>` | Додати відповідального за майстер-клас (ID — номер `№` з каталогу) |
| `/syncresp` | Синхронізувати відповідальних із каталогу (стовпець «Відповідальний», кілька імен через «і»/«й»/«та»/кому) — додає лише відсутніх, нічого не видаляє |
| `/delresp` | Видалити відповідального: бот показує кнопки з іменами, згрупованими по майстер-класу, з підтвердженням перед видаленням |
| `/broadcast <текст>` | Розсилка всім учасникам, що пройшли чек-ін |

---

### Суперадмін

Суперадмін — Telegram ID зі змінної оточення `ADMIN_IDS`. Має всі права адміна плюс:

| Команда | Опис |
|---|---|
| `/addadmin <TelegramID> <Ім'я>` | Додати адміна |
| `/removeadmin <TelegramID>` | Видалити адміна |
| `/listadmins` | Список адмінів |

> Надіславши відео або кружечок боту, суперадмін отримає `file_id` для ручного використання.

## Налаштування

### 1. Telegram-бот

- Створіть бота через [@BotFather](https://t.me/BotFather) → отримайте `BOT_TOKEN`.
- Дізнайтесь свій Telegram ID (наприклад, через @userinfobot) → `ADMIN_IDS`.

### 2. Google Sheets

- У [Google Cloud Console](https://console.cloud.google.com) створіть проєкт → увімкніть **Google Sheets API** → створіть **Service Account** → згенеруйте JSON-ключ.
- З ключа візьміть `client_email` → `GOOGLE_SERVICE_ACCOUNT_EMAIL` і `private_key` → `GOOGLE_PRIVATE_KEY`.
- **Поділіться таблицею** з email сервісного акаунта (роль Editor).
- `SHEET_ID` — частина URL таблиці між `/d/` і `/edit`.

Структура вкладок:

| Вкладка | Заголовки | Примітки |
|---|---|---|
| Відповіді форми | _(заголовки з форми)_ + `Checked in`, `Telegram ID` | Також читаються `Команда` (числовий ID) і `Кімната` |
| `MCSchedule` | `Date \| Slot \| MC IDs` | `Date` — `YYYY-MM-DD`; `Slot` — коротка мітка (напр. `12:00-13:00`), вбудовується в callback-дані; `MC IDs` — `№` з каталогу через кому |
| `EventRegs` | `Date \| Slot \| MC ID \| Telegram ID \| Name \| Registered at \| Cancelled at` | Реєстрації на майстер-класи; бот заповнює автоматично; одна активна реєстрація на слот |
| `MCResponsible` | `MC ID \| Name \| Telegram ID \| Added at` | Бот заповнює через `/addresp`; одна людина може мати кілька рядків (кілька МК) |
| `Videos` | `ID \| Team \| File ID \| Type` | `ID` — числовий незмінний ключ; `Type` — `video_note` або `video` |
| `Admins` | `Telegram ID \| Name` | Бот заповнює через `/addadmin` |
| `Leaders` | `Team \| Name \| Telegram ID \| Linked at` | Колонка `Team` — числовий ID команди |

> Каталог майстер-класів (назва, місце, ліміт місць) **не** зберігається в цій таблиці — бот читає його на льоту з окремої таблиці «Сітка табору» (`GRID_SHEET_ID`, вкладка `5.Майстер-класи 2026`), див. розділ нижче.

### 3. Деплой на Vercel

1. На [vercel.com](https://vercel.com) → **Add New Project** → імпортуйте репозиторій з GitHub.
2. У **Settings → Environment Variables** додайте всі змінні з `.env.example`.
3. Vercel задеплоїть проєкт автоматично. Надалі кожен пуш у `main` → автодеплой.

Після першого деплою зареєструйте webhook (один раз):

```bash
cp .env.example .env   # заповніть VERCEL_URL та інші значення
npm run set-webhook
```

### 4. QR-код для плаката

```bash
npm run qr   # створює checkin-qr.png (потрібен BOT_USERNAME у .env)
```

## Спільна таблиця «Сітка табору» (`GRID_SHEET_ID`)

Організатори ведуть окрему таблицю **«Discovery 2026 AI сітка»** (доступ лише на читання). Сервісний акаунт бота вже може її читати — достатньо вказати її ID у змінній `GRID_SHEET_ID` (необов'язкова; без неї кнопка «🎨 Майстер-класи» відповідає «Сьогодні майстер-класів немає», а «🗓 Розклад» — «Розклад тимчасово недоступний»).

Вкладки, які бот читає наживо:

| Вкладка | Структура | Що робить бот |
|---|---|---|
| `3.Розклад табору 2026` | Сітка: колонка A — час, колонки B–G — дні, колонка J — «Розклад по Легенді» | Кнопка **🗓 Розклад** показує розклад поточного дня прямо з сітки |
| `5.Майстер-класи 2026` | Таблиця: №, Назва, Відповідальний, Місце проведення, …, Кількість учасників | Каталог майстер-класів: заголовний рядок шукається автоматично (перший рядок із «Назва»); `№` виду `1.` → ID `1`; `без обмежень`/порожньо → без ліміту; рядки без числового `№` (турнірні таблиці нижче) ігноруються |

Хто саме проводить майстер-клас і скільки на нього зареєструвались — визначається окремо, в основній таблиці (`MCSchedule`, `EventRegs`, `MCResponsible`); стовпець «Відповідальний» у каталозі — лише довідковий текст.

**Застереження:**

- Таблиця оформлена «для людей»: об'єднані клітинки, службові позначки (`on`, `off`, `.`). Парсер читає лише відомі діапазони, а не всю вкладку.
- Якщо організатори змінять структуру (пересунуть колонку/рядок), живе читання може зламатись.
- Запис у цю таблицю не потрібен: усі дані бота (реєстрації, чек-іни, відповідальні) лишаються в основній таблиці `SHEET_ID`.

## Технічні нотатки

- `api/cron/mc-reminder.ts` — Vercel Cron нагадування тим, хто ще не зареєструвався на найближчий слот майстер-класів. Дві крон-задачі в `vercel.json` (`0 8 * * *` і `0 10 * * *` UTC = 11:00/13:00 Києва влітку) з параметром `?before=12:00`/`?before=14:00`, захищені `CRON_SECRET`. На тарифі Hobby крон-завдання спрацьовує в будь-яку хвилину зазначеної години (ніколи раніше, іноді пізніше) — точний час не гарантується.
- Ліміт місць перевіряється при реєстрації; за одночасних кліків можливий незначний перебір — для табору це прийнятно.
- Стара функція «Події» (`Events`) видалена й замінена майстер-класами: реєстрація тепер прив'язана до дати+слоту+ID майстер-класу, а не до окремого `Event ID`. Тестів немає, але `npm run dev` запускає локальний dev-сервер (`scripts/dev.ts`) у режимі long polling для ручної перевірки — він читає той самий `.env`, тож токен бота й таблицю варто підмінити на тестові, а не використовувати бойові дані табору. Перевірка — через `npm run typecheck`, `npm run dev` і ручну перевірку після деплою.
- Кількість вільних місць на кнопках у «🎨 Майстер-класи» — це знімок на момент відкриття повідомлення; після чиєїсь реєстрації клавіатура не оновлюється сама, повторне відкриття покаже актуальні числа.
- У бота немає глобального `bot.catch`: помилка в обробнику стає HTTP 500, і Telegram повторно надішле те саме оновлення. Для великого каталогу майстер-класів `/syncresp` розбиває відповідь на кілька повідомлень (ліміт ~3500 символів на повідомлення), щоб не впертися в обмеження Telegram (4096 символів).
- Клавіатура `/delresp` не має пагінації — розрахована на типовий розмір списку відповідальних (10-15 осіб); при значному зростанні каталогу може знадобитись розбиття на сторінки.
